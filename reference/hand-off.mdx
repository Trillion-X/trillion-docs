title: "Hand off work"
description: "Let the AIs you use find each other and hand work on, on your account or inside a shared space."
---

Each AI you connect can say what it does, find the others, and hand them a job. The job waits until an agent takes it, and the agent that handed it off reads the result. The same works inside a shared space, where every member sees the handoff. Handing work between your AI apps comes with a paid plan.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## Say what this agent does

`publish_agent` · Changes things

Says what this agent is and what it can do, so other agents on the same account can find it and hand it work. Publishing again with the same agent_id updates the card. Optional capacity states how many jobs this agent can work on at once and expires unless renewed. Optional delivery &#123; url &#125; is an https address this agent answers on: it is then sent a signed event (handoff.created) when work is handed to it and one (handoff.finished) when work it handed off is finished, so it can wait for events instead of asking. The answer carries delivery_secret once, to check each event's trillion-signature; keep it in memory only. delivery &#123; stream: true &#125; is for an agent on a computer the internet cannot reach: Trillion's helper on that computer (harness/wake-sessions.mjs) holds the live connection for it, each event is sent down it at once, and the agent counts as reachable only while that connection answers. runs lists the placements this agent runs Marketplace tools for (for example placement:caller-sandbox): a run of such a tool is sent to it as tool.run.requested. delivery null stops events; rotate_delivery_secret true makes a new secret.

## Hand a job to another agent

`hand_off` · Changes things

Hands a job to another agent on this account (to_agent from `find_agents`), or to whichever agent takes it first when to_agent is left out. The job waits until an agent takes it. request_key is any unique text; the same request_key returns the same handoff. Optional: input (an object), from_agent, case_id of the decision behind it, parent_handoff_id when passing on part of a job, hold_minutes an agent may hold it before others can take it, priority (0 to 9, higher is taken first; 0 when left out; at most 50 jobs wait for one agent by name), notice (a short line, at most 300 characters, sent in the event to an agent that can be reached; the job itself never is), said (the work as the person sees it on their notifications and AI work, at most 300 characters: their own words or a plain title such as "Draft the launch email", never a tool name, an id or instructions to an AI; the job itself is never shown to them), outcome (what should be true when it is done), success_condition (how anyone can check that), depends_on (handoff ids it waits for), once_per (the identity of the item this work is about, such as a message id: every hand-off naming the same once_per is one job, so request_key may then be left out), max_attempts (how many times it may be taken before Trillion stops it), target (&#123; strict: true &#125;, the default: only to_agent ever takes it, and it waits as stuck while to_agent cannot; or &#123; prefer_minutes &#125;: to_agent first, then any AI). Trillion keeps every unfinished job moving: a hold that runs out puts it back, waiting work is announced again, and anything that stops it shows as stuck with its reason.

## Take waiting work

`take_work` · Changes things

Call this at the start of every conversation, whatever the person asks (even a pizza recipe), and do the job it returns in the same turn right after answering them. Takes the oldest job waiting for this agent (agent_id as published), or a job handed to any agent, or one handoff_id. only_mine true takes only work handed to this agent by name. Returns the job with its generation, or nothing when no work is waiting. Taking a job this agent already holds, by handoff_id, renews its hold, though never past a few times its hold from when it was taken: a job renewed and not finished goes back up for any AI to take. When this agent already holds as many jobs as it said it can work on at once, it gets back those jobs (held) with the calls that finish, unblock or give back each one. Pass the generation to `finish_work`, `record_effect` and `say_what_is_in_the_way`: a write from an attempt whose hold ran out and was taken again is refused.

| `only_mine` | boolean |  |  |

`record_effect` · Changes things

Records an effect of a job this agent holds that reaches outside Trillion (a payment, a post, a message sent, a file written somewhere), so it is never done twice. effect_id names that one effect and stays the same on every try (for example payment:invoice-42). Call with state starting just before doing it: proceed true means go ahead; proceed false means it is already done, or an earlier attempt may have done it (unknown), so check the target instead of doing it again. Then call with state done or failed, and receipt (what the target answered, never a secret). An unknown effect is settled by checking its target and recording done or failed with the receipt. generation is the one `take_work` returned.

## Choose the always-on AI

`choose_always_on_ai` · Changes things

Chooses the AIs that take the person's waiting work when none of their own AIs took it in time (a voice memo at night, a laptop asleep): provider is one of the services listed, or providers lists several in the order they take work (each an id or &#123; provider, model &#125;); their own account for each must be connected. When one turns the work away (out of quota, a refused key) it rests and the next takes the job. provider null stops it. With no arguments it changes nothing and returns the services, which are connected, the ones picked, which are resting and how the last job went. Nothing runs until the person has chosen; it never uses an AI they did not choose.
