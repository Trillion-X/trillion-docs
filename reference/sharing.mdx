title: "Sharing"

Every record you keep, a goal, a decision, a message, a file or a tool, can be shared with the Trillion network, a shared space or particular people, or kept to yourself. These tools read and change those choices, and set where the pages and files you send to Trillion go.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## See who a record is shared with

`sharing_of` · Reads only

Who one of this person's records is shared with, as the sharing sheet shows it: the copy others would see (preview, only the fields that leave), its fields with which are left out, every place it can go (the Trillion network, each space they are in, each person they share a space with) with picked true for where it goes now, the chain switch (the record together with the records linked to it, like a pursuit and its decisions) and inherited_from when a chain choice on another record decides it. It changes nothing.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `record` | string | Yes | A pursuit id, decision case_id or message id; file:&#60;identity&#62; for a file; tool:&#60;id&#62; for one of their own tools; workflow:&#60;id&#62; for a workflow |

```json Example
{
  "record": "<record>"
}
```

## Choose who a record is shared with

`set_sharing` · Changes things

Chooses who one of this person's records is shared with, only when they asked. network: true into the network (anonymous learning, and stories when those are on), false never, null as their account chooses (on by default). spaces: the space ids a copy is in; people: the people (the `to.person` of a place from `sharing_of`) who may read it. Not shared at all is network false with no spaces or people. chain: true to cover the records linked to it too. leave_out: field ids no copy carries. Parts left out stay as they are. Copies made elsewhere are changed to match at once. Returns what `sharing_of` returns.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `record` | string | Yes | A pursuit id, decision case_id or message id; file:&#60;identity&#62; for a file; tool:&#60;id&#62; for one of their own tools; workflow:&#60;id&#62; for a workflow |
| `network` | boolean or null |  |  |
| `spaces` | string[] |  |  |
| `people` | string[] |  |  |
| `chain` | boolean |  |  |
| `leave_out` | string[] |  |  |

```json Example
{
  "record": "<case_id>",
  "network": false,
  "spaces": [
    "<space_id>"
  ]
}
```

## Send a share where I share

`deliver_share` · Changes things

Sends one selection to places this person shares to (to: ids from `share_destinations`). Items may mix source records, files, workflows, tools, links, words and another open share. Their own Trillion gets it handed to their AI with every chosen action's words and own_words as the job, once to each AI in to_agent (one or a list; left out, whichever is free); an action that keeps examples saves each shared link first, and an action with a workflow starts it on the share. Each Space receives the mixed selection in one request: files, records, workflows and tools stay with their owner, while links and words become Space items. Each tool place runs its tool once with the share. Returns delivered (&#123; id, label &#125; each), stopped_at (&#123; id, label, error &#125;, or null when every place has it): the places before stopped_at have it, handoff_ids (the jobs handed to their AI, each readable with `read_handoff`) and workflow_runs (the runs started, each readable with `read_workflow_run`).

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `to` | string[] | Yes | Place ids from `share_destinations` destinations |
| `items` | object[] | Yes |  |
| `items[].kind` | string |  |  |
| `items[].url` | string |  |  |
| `items[].title` | string |  |  |
| `items[].text` | string |  |  |
| `items[].record` | string |  | A record reference from this person's Trillion; the owner checks its current sharing choice on every Space read |
| `items[].file` | string |  | A kept file's identity in this person's files |
| `items[].workflow_id` | string |  | A saved workflow ID |
| `items[].tool_id` | string |  | A saved tool ID |

| `items[].name` | string |  |  |
| `request_key` | string | Yes |  |
| `action` | string or string[] |  | One action id from `share_destinations`, or a list of them (the AI is asked to do each); left out, the action the first address's site starts on |
| `own_words` | string |  |  |

## Make a link to a record

`share_record_by_link` · Changes things

Makes an expiring or open-ended link to one or several records others may read. records lists up to 99 additional record references for one link. scope is &#123; kind: "public" &#125;, &#123; kind: "private", value: recipient relay &#125;, &#123; kind: "email", value: address &#125;, &#123; kind: "phone", value: international number &#125;, or &#123; kind: "code", value: access code &#125;. Recipient-bound links require verified identity when opened. can lists what the recipient may do beyond seeing it (view, sign, pay; each kind of record offers its own, and sign and pay ask the recipient to prove their email with a code, no account needed). when is a rule tree (formula-engine shape) over now, opened, signed, paid and status that must hold for the link to open. look is own (the account brand, see `share_look`) or trillion. Every link opens on /share/&#60;code&#62;. Returns the opaque link code once, its address and its expiry.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `record` | string | Yes | A pursuit id, decision case_id or message id; file:&#60;identity&#62; for a file; tool:&#60;id&#62; for one of their own tools; workflow:&#60;id&#62; for a workflow |
| `records` | string[] |  |  |
| `scope` | object | Yes |  |
| `scope.kind` | string | Yes | One of `public`, `private`, `email`, `phone`, `code`. |
| `scope.value` | string |  |  |
| `expires_at` | string or null |  |  |
| `can` | string[] |  |  |

## Put a record in or out of a pursuit or space

`set_record_scope` · Changes things

Puts one of this person's records into pursuits or spaces, or takes it out, as their own choice, only when they asked. add and remove each take pursuits (ids from `list_pursuits`) and spaces (ids from `list_spaces`). Removing takes it out even where its own links put it. A pursuit put into another pursuit is set under it, so pursuits nest as a tree (`list_pursuits` returns parents and children); one pursuit can sit under several, and never under itself or a pursuit inside it. Choosing a space never shares the record there; `share_to_space` does that. A pursuit reparenting returns its parents and children; other writes return what `record_scope` returns.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `record` | string | Yes |  |
| `add` | object |  |  |
| `add.pursuits` | string[] |  | Pursuits ids |
| `add.spaces` | string[] |  | Spaces ids |
| `remove` | object |  |  |
| `remove.pursuits` | string[] |  | Pursuits ids |
| `remove.spaces` | string[] |  | Spaces ids |

```json Example
{
  "record": "<record>"
}
```
