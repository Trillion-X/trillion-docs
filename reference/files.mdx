Your files live in your Trillion, where any AI you connect can find, read and show them. Big files are sent in pieces or straight from a computer. What an AI works out about a file, like a transcript or a summary, is kept so no AI has to work it out again. Files come with a paid plan.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## List a folder of my files

`list_files` · Reads only

Lists one folder of this person's namespace: the folders inside it (folders), and each file named in it with its content identity and whether its bytes are stored (stored: true), or are still arriving (stored: false with uploading: its upload id, bytes_held and byte_length). A file that is one of several versions of the same file in that folder (the same name with a copy number, a version number, an export time or a backup mark) carries version &#123; family, latest, latest_name, versions &#125;: work from the one with latest: true, and the older ones stay there to go back to. A file whose same bytes are also kept under other names carries also_named (how many), so the same work is not done twice. Start at folder "/" and open a folder by passing its name as folder; pass next_after as after for the next page of files.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `folder` | string |  |  |
| `after` | string |  |  |
| `limit` | integer |  |  |

```json Example
{
  "folder": "/"
}
```

Finds one of this person's files in their namespace by its path name (starting with /) or its content identity (1f: or 12: then 64 hex). Returns the size, type, where it is kept, every name it has, and a url that reads it (ranges supported) until url_expires_at, plus its locator rows for any resolver.

**Inputs**

| --- | --- | --- | --- |
| `name_or_identity` | string | Yes |  |

## Read one of my files

Reads what one of this person's files contains, by its path name (starting with /) or content identity: up to 256 KiB from offset, as text when those bytes are UTF-8 text and as base64 otherwise. Read longer files a range at a time. A picture (PNG, JPEG, GIF or WebP) up to 3 MiB comes back whole as an image you can look at, with a link to it; a bigger picture comes back as a link. Reading a file does not show it to the person: use `show_file` for that.

## Save a file

`write_file` · Changes things

Saves a file in this person's namespace under name (a path starting with /, such as /edits/cover-cut.json), from exactly one of: text (UTF-8: a transcript, a note, an edit as JSON); content_base64 (a small file's bytes, at most 16 MiB); from_url (an https address that serves the file itself, which Trillion reads, any size); or file (a file from this chat, as the app hands it over: &#123;download_url, file_id&#125;). Never type a large file out as base64: give its address, or `start_file_upload` and send its bytes from your computer to send_bytes_to. With only file, name defaults to /&#60;its file name&#62;. media_type (optional) is its type, such as audio/mpeg or application/json; text without one is saved as text/plain. Returns the file's content identity (1f: then 64 hex), which `run_tool` accepts wherever a tool takes a file, and its name. Bytes this person already has are only given the name (already_kept: true). A name already in use then points at the new file; the earlier file stays readable by its identity.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `name` | string |  |  |
| `content_base64` | string |  | The bytes, base64 |
| `text` | string |  | The bytes as UTF-8 text, instead of content_base64 |
| `from_url` | string |  | An https address that serves the file itself; Trillion reads the bytes from it |
| `file` | object |  | A file from this chat: &#123;download_url, file_id&#125;, as the app hands it over |
| `file.download_url` | string | Yes |  |
| `file.file_id` | string | Yes |  |
| `file.mime_type` | string |  |  |
| `file.file_name` | string |  |  |
| `media_type` | string |  |  |

```json Example
{
  "name": "/notes/ideas.md",
  "text": "Three ideas for the launch email."
}
```

## Start saving a big file

`start_file_upload` · Changes things

Starts saving a file that is on a computer you can run commands on, or too big for one `write_file` call: name (a path starting with /), byte_length (its exact size in bytes) and media_type. Returns upload (its id), send_bytes_to and send_with: from that computer run curl -sS -T &#60;file&#62; "&#60;send_bytes_to&#62;" and the file is finished when its last byte arrives (a file over 90 MB goes in parts, each with &offset=&#60;its first byte&#62;). Without a computer, send it with `put_file_piece`, piece 0 first (at most max_piece_bytes each), then `finish_file_upload`. Starting the same name again stops the earlier unfinished upload of that name. From its first piece the file can be found, read and played by its name while the rest arrives. If you know the file's BLAKE3 identity, give it as identity: a file this person already has is then only named (state: present) and nothing needs sending.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `name` | string | Yes |  |
| `byte_length` | integer | Yes |  |
| `media_type` | string |  |  |
| `identity` | string |  |  |

```json Example
{
  "name": "/recordings/interview.mp4",
  "byte_length": 734003200,
  "media_type": "video/mp4"
}
```

## Search everything I keep
