These tools change what the person sees in Trillion: their lists and the rows in them, the sidebar, screen layouts, guided tours and screen looks, and a Trillion screen drawn right in the chat.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## List my lists

`list_lists` · Reads only

The lists this person keeps (their CRM, customers, the AIs in a space, anything): each list's id, label, fields and how many rows it holds. It changes nothing; `read_list` reads one list's rows. On the person's screen (Lists), use it when they keep track of several things of one kind across messages, files or notes: make the list, fill it from what you found, then show it with a tour or a layout.

It takes no inputs.

## Read a list and its rows

`read_list` · Reads only

One list with its rows: each row's id, title (the value of its title field), values by field id, and for each link field the linked rows with their titles. Also field_kinds, the kinds a field can have. It changes nothing. On the person's screen (Lists), use it when they keep track of several things of one kind across messages, files or notes: make the list, fill it from what you found, then show it with a tour or a layout.

## Make or change a list

`save_list` · Changes things

Keeps a list: give label and fields to make one (its id is made from the label), or id with the whole fields list to change one, such as adding a field. A link field (kind "link", links_to another list's id) holds rows of that list, so a Customers list can link each customer to their CRM row. row_type (optional, only when making a list) names the kind of the person's records its rows are: rows other tools already keep, such as "customer", show in the list as they are. title_field names the field that is each row's name (the first field when left out). views are saved slices of the rows (Customers, Leads), kept on the list. Rows are kept. On the person's screen (Lists), use it when they keep track of several things of one kind across messages, files or notes: make the list, fill it from what you found, then show it with a tour or a layout.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `id` | string |  | A list id from `list_lists`, like "trillion-crm" |
| `label` | string |  | The name people see, like "Trillion CRM" |
| `fields` | object[] |  | Every field, in order: sending fields replaces the list's fields |
| `fields[].id` | string |  | Short name of letters, digits, dashes or underscores; made from the label when left out |
| `fields[].label` | string | Yes |  |

| `fields[].choices` | string[] |  | For a choice field: the choices, in order |

## Read my sidebar

## Point to a list or row in my sidebar

`note_in_sidebar` · Changes things

Points the person to a list or row in their sidebar: on is a list_id or row_id from `read_sidebar`; message is what you want them to do there, in a sentence; count a number to show on it; highlight true marks it; opens names screens (row_ids) offered in its hover card. The note shows on that list or row and when the person points at it, and a message also reaches their notifications once. One note per list or row: a new one replaces it, and a note with only on takes it off. Take it off once they did it. On the person's screen (The sidebar), use it when something waits for them in one place, put a note with a count there and take it off once they did it; when things they keep coming back to belong together, make a list of them; when something matters only for a while, show it only for that while (shown_when).

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `on` | string | Yes | A list_id or row_id from `read_sidebar` |
| `message` | string |  | What you want the person to do there, in one sentence |
| `count` | integer |  | A number to show on it, such as how many things wait there |
| `highlight` | boolean |  | true marks it so it stands out |
| `opens` | string[] |  | row_ids of screens to offer in its hover card |

## Change my sidebar lists

`change_sidebar` · Changes things

Changes the person's sidebar lists, in order, as one change: &#123; do: "make_list", name, list_id?, holds?, order_by?, shown_when? &#125; makes a list; &#123; do: "`set_rule`", list_id, row_id?, holds?, order_by?, shown_when? &#125; puts rules on one of their own lists, or on one row of it (shown_when only), null taking a rule off. holds is a rule over each row's facts and the list holds every row it is true for (beside that row's own list); shown_when is a rule over the list's facts (or, with row_id, the row's) and it shows only while the rule holds; order_by is &#123; path: ["listed_on"], descending: true &#125;. A rule is the formula engine's tree &#123; kind: "group", combinator: "and" | "or", negate: false, rules: [&#123; kind: "rule", field, operator, params &#125;] &#125; over the facts `read_sidebar` lists under facts (now is a date in milliseconds; days_since_made, days_since_listed and the like are numbers). For 7 days after it is made: &#123; field: "days_since_made", operator: "less_than", params: &#123; value: 7 &#125; &#125;; until a time: &#123; field: "now", operator: "before", params: &#123; value: &#60;ms&#62; &#125; &#125;. Rules are decided again as time passes, so a list or row comes and goes by itself; `read_sidebar` shows those hidden now under not_shown_now; &#123; do: "rename_list", list_id, name &#125;; &#123; do: "remove_list", list_id &#125; deletes one of their own lists; &#123; do: "add", list_id, row_id &#125; puts any row (a screen or a tool) in a list, which may hold rows of any kind; &#123; do: "remove", list_id, row_id &#125; takes it out; &#123; do: "order", list_id, row_id, before | after | at &#125; moves it within the list; &#123; do: "move", from_list_id, list_id, row_id &#125; moves it to another list; &#123; do: "style", row_id, colour?, place? &#125; draws a row in a colour (grey, blue, turquoise, green, yellow, orange, red, pink, purple) and keeps it in a place of the sidebar ("bottom": at the foot below every list; "controls": among the icons at the top), null putting either back. A list of Trillion's own becomes the person's copy on its first change. Returns the lists as they are now. On the person's screen (The sidebar), use it when something waits for them in one place, put a note with a count there and take it off once they did it; when things they keep coming back to belong together, make a list of them; when something matters only for a while, show it only for that while (shown_when).

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `changes` | object[] | Yes |  |
| `changes[].do` | string | Yes | One of `make_list`, `rename_list`, `remove_list`, `add`, `remove`, `order`, `move`, `style`, `set_rule`. |
| `changes[].list_id` | string |  | A list_id from `read_sidebar` (for make_list, an id of your choosing, made for you when left out) |
| `changes[].from_list_id` | string |  | For move: the list the row is in now |
| `changes[].row_id` | string |  | A row_id from `read_sidebar` |
| `changes[].name` | string |  | For make_list and rename_list: what the list is called |
| `changes[].colour` | string or null |  | For style: a colour of the palette, or null for the app's own |
| `changes[].place` | string or null |  | For style: bottom or controls, or null to keep it in its lists |
| `changes[].holds` | object or null |  | For make_list and `set_rule`: a rule tree over each row's facts; the list holds every row it is true for |
| `changes[].order_by` | object or null |  | With holds: &#123; path, descending? &#125;, the row value its rows are ordered by |
| `changes[].shown_when` | object or null |  | For make_list and `set_rule`: a rule tree over the list's facts (or, with row_id, the row's); it shows only while the rule holds |
| `changes[].before` | string |  | Put it just before this row_id in the same list |
| `changes[].after` | string |  | Put it just after this row_id in the same list |
| `changes[].at` | string |  | Put it first or last One of `start`, `end`. |

```json Example
{
  "changes": [
    {
      "do": "make_list"
    }
  ]
}
```

## Write a guided tour on my screen

The same id again changes that tour. remove true with tour.id takes it away. Returns the tour kept. On the person's screen (Guided tours), use it after you finish work they can see (a file you made, a list or layout you built, something you fixed or connected), end the turn with a short tour pointing at it (`save_tour` with show_now true); also when they ask how something works or where something is. On the person's screen (What's new), use it when something they use changed while they were away (you connected a service, added a tool, changed their lists), shown once the next time they are on their page.
