title: "Shared spaces"
description: "Work with other people in a group, project or event: invite them, share into it, and decide who may do what."

A shared space is a group, project, event, community or one-to-one you work in with other people. It holds only what members put there; nobody, and no agent, can read another member's private Trillion through it. Spaces come with a paid plan.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## List my shared spaces

`list_spaces` · Reads only

The shared spaces this person is in (groups and projects with other people), each with its description and picture, the names its members show there, how many items of each kind it holds, unread (items other members added since this person last marked it seen) and last_activity_at. A space holds only what members put there; nobody, and no agent, can read another member's private Trillion through it.

It takes no inputs.

```json Example
{}
```

## Start a shared space

`create_membership` · Changes things

Starts a shared space with this person as its first member and owner: a group, project, event, community or one-to-one (label). Every one is a shared space (`list_spaces`, `share_to_space`, `add_to_space`, `hand_off_in_space`); events take starts_at and ends_at; size_limit caps members. Invite people into a group or project with `request_introduction` and its membership_id. A community is joined by its own rules instead (anyone may join with `join_community` when its join rules let them, and it never shares anyone's contact); it starts with the community label's starting configuration, and config replaces any of its keys (title comes from title). Its posts are the space's messages.

**Inputs**

## Share one record into a space

`share_to_space` · Changes things

Shares one record from this person's private Trillion into a space they are in, and nothing else: record_id is one pursuit id, decision case_id or message id, file is one file's name or identity, or tool is one of their own saved tools' id (its descriptor and file texts are copied, so another member's AI can keep its own copy with `save_tool`). Only the fields meant for others are copied (a decision leaves behind the pursuits it was weighed against); a file's bytes stay with the person and members read them through the space. Sharing the same record again updates the copy. Only share what the person asked to share.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `space_id` | string | Yes | A space_id from `list_spaces` |
| `record_id` | string |  |  |
| `file` | string |  |  |
| `tool` | string |  |  |

```json Example
{
  "space_id": "<space_id>",
  "record_id": "<case_id>"
}
```

## Read who may do what in a space

`read_space_rules` · Reads only

Who may do what in one shared space: its rules, each with id, effect (allow or deny), says (what it means), who, actions and when (further conditions, a rule tree over facts), what each covers, the facts, kinds of who and actions a rule can name, the members a rule can name (member_id, name, member_type), and may_change (whether this person may replace them). Every space starts with rules that let its members read, write, share, invite and hand work, let whoever put something there take it back, and let whoever started it change the rules. ## Change who may do what in a space

`set_space_rules` · Changes things and can remove them

Replaces who may do what in one shared space, for a person its rules let change them (at first, whoever started it). Send the whole list, `read_space_rules` first and change it: each rule is &#123; id, effect: "allow" or "deny", says: what it means in plain words, refuses?: the words a deny says to the person it stops, who?: &#123; kind: "anyone" &#125; or &#123; kind: "any_member" &#125; or &#123; kind: "anyone_with_link" &#125; or &#123; kind: "member_type", member_type &#125; or &#123; kind: "person", person: a member_id from `read_space_rules` &#125;, actions?: [action ids] (every action when left out), when?: &#123; kind: "group", combinator: "and" or "or", rules: [conditions or groups] &#125; &#125;, a condition being &#123; kind: "rule", field: one of the facts, operator: "is_any_of" or "is_none_of", params: &#123; values: [...] &#125; &#125; (is_member, is_owner, holds_link, made_it, maker_is_member and is_community are true or false; action, member_type and person are ids). A rule holds when its who, actions and when all hold. A deny that holds wins; otherwise an allow that holds lets the person act; when none holds they are refused. Who may change the rules is the action change_rules in the same list, and a list that would stop this person changing them again is refused. rules null puts back the rules every space starts with. Every member sees the new rules; say what will change and get the person's approval first.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `space_id` | string | Yes | A space_id from `list_spaces` |
| `rules` | object[] or null | Yes |  |

```json Example
{
  "space_id": "<space_id>",
  "rules": "<rules>"
}
```
