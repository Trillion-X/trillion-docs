A shared space is a group, project, event, community or one-to-one you work in with other people. It holds only what members put there; nobody, and no agent, can read another member's private Trillion through it. Spaces come with a paid plan.

You do not call these tools yourself. You ask your AI in plain words, and it picks the tool. This page shows what each one does, so you know what to ask for.

## List my spaces

`list_spaces` · Reads only

The spaces this person is in (groups and projects with other people), each with its description and picture, the names its members show there, how many items of each kind it holds, unread (items other members added since this person last marked it seen) and last_activity_at. A space holds only what members put there; nobody, and no agent, can read another member's private Trillion through it.

It takes no inputs.

```json Example
{}
```

## Start a space

## Change who may do what in a space

`set_space_rules` · Changes things and can remove them

Replaces who may do what in one space, for a person its rules let change them (at first, whoever started it). Send the whole list, `read_space_rules` first and change it: each rule is &#123; id, effect: "allow" or "deny", says: what it means in plain words, refuses?: the words a deny says to the person it stops, who?: &#123; kind: "anyone" &#125; or &#123; kind: "any_member" &#125; or &#123; kind: "anyone_with_link" &#125; or &#123; kind: "member_type", member_type &#125; or &#123; kind: "person", person: a member_id from `read_space_rules` &#125;, actions?: [action ids] (every action when left out), when?: &#123; kind: "group", combinator: "and" or "or", rules: [conditions or groups] &#125; &#125;, a condition being &#123; kind: "rule", field: one of the facts, operator: "is_any_of" or "is_none_of", params: &#123; values: [...] &#125; &#125; (is_member, is_owner, holds_link, made_it, maker_is_member and is_community are true or false; action, member_type and person are ids). `set_space_capability` · Changes things

Turns one part of any space on or off (on: true or false), whatever kind of space it is: a project, a group or a community. The parts: points (Everyone earns points for what they do here and moves up levels); leaderboard (Everyone in order of their points, with their level; turns on points too); rewards (Something people claim once they have enough points; turns on points too); streak (How many weeks in a row each person wrote something here); events (A calendar of calls and meetups, with who is going); classroom (Courses with lessons each person marks done); votes (Everyone votes for the messages that matter most, and those come first); matching (Everyone's own AI suggests who here should talk each week, and why); digests (An email to whoever asks for one when something new happened, at most once a week); board (A canvas everyone here works on at once: pictures, notes and ideas, with each other's cursors). Turned on the first time, a part starts with sensible settings; turned off, what it had is kept and comes back when it is turned on again. The space's own rules decide who may (at first its owner). Returns every part with whether it is on; read the parts themselves with the community tool and the space id.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `space_id` | string | Yes | A space_id from `list_spaces` (or a community id) |
| `capability` | string | Yes | One of `points`, `leaderboard`, `rewards`, `streak`, `events`, `classroom`, `votes`, `matching`, `digests`, `board`. |
| `on` | boolean |  | false turns it off; true when left out |

```json Example
{
  "space_id": "<space_id>",
  "capability": "points"
}
```

## Start a space

`create_space` · Changes things

Starts a new space with this person as its owner and first member (a project unless label says group), the same as the New project button on the Spaces screen, and invites each person in members the way `invite_to_space` does (a one-time link, emailed when email is given and texted when phone is given). Returns the new space_id and, per person, the link and whether each message went out. Only invite people the person asked to invite.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `name` | string | Yes | What the space is called |
| `label` | string |  | project when left out One of `project`, `group`. |
| `members` | object[] |  | People to invite into it |
| `members[].name` | string |  |  |
| `members[].email` | string |  |  |
| `members[].phone` | string |  |  |

```json Example
{
  "name": "<name>"
}
```

## Invite someone into a space

`invite_to_space` · Changes things

Invites one person into a space and tells them: makes a one-time invite link, writes the invitation (an email and a short text in this person's voice, both with the link, whose preview shows the space, who invited them and who is in it), emails it when email is given, and texts it when phone is given through this person's own connected iMessage or WhatsApp (text_through; iMessage when left out). Returns the link, the email and the text as written, and whether each went out; a text that could not go out is returned for you to send. Only invite someone the person asked to invite.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `space_id` | string | Yes | A space_id from `list_spaces`, or the space's name (its whole name or one word only it has), so posting to a space the person named needs no `list_spaces` first |
| `name` | string |  | The name of the person invited, as the invitation greets them |
| `email` | string |  | Where the invitation email goes |
| `phone` | string |  | The number the text goes to |
| `text_through` | string |  | Which of this person's connected accounts sends the text One of `imessage`, `whatsapp`. |
| `days` | number |  |  |

```json Example
{
  "space_id": "<space_id>"
}
```

## Grant a Workshop tool in a space

`grant_space_tool` · Changes things

Grants one current Space member specific operations on a published Workshop tool. Name member_id to grant someone else; leaving it out grants only yourself. Name operations to limit use; leaving them out grants discover, describe, run and read. It stores a definition reference, never tool code or private connections. Only the person who started the space can grant it.

**Inputs**

| Input | Type | Required | What it is |
| --- | --- | --- | --- |
| `space_id` | string | Yes | A space_id from `list_spaces`, or the space's name (its whole name or one word only it has), so posting to a space the person named needs no `list_spaces` first |
| `tool_id` | string | Yes |  |
| `tool_version` | string |  |  |
| `member_id` | string |  |  |
| `operations` | string[] |  |  |

```json Example
{
  "space_id": "<space_id>",
  "tool_id": "<tool_id>"
}
```
